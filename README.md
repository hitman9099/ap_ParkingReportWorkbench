# 停车报表工作台

停车报表工作台是 Windows 免安装客户端。它读取运营台账中的地块名称，在利民停车管理平台查找车场，逐个入场通道导出车辆进出记录，核验报表后生成一份填有月总停车时长的台账副本。

[下载 ANPING.exe（Windows x64）](https://github.com/hitman9099/ap_ParkingReportWorkbench/releases/latest/download/ANPING.exe) · [查看版本和 SHA-256](https://github.com/hitman9099/ap_ParkingReportWorkbench/releases/latest)

## 快速开始

1. 将 `ANPING.exe` 保存到有写入权限的本地目录，双击运行。便携版内置 Chromium 和 Python 工作程序。
2. 点击「验证浏览器」。如果弹出平台登录窗口，在窗口中输入停车平台账号和密码并手动完成验证。账号须有对应项目的查询和报表导出权限。
3. 选择 `.xlsx` 台账、统计起止日期和输出目录。起止日期均包含在查询范围内。并行车场数可选 1 至 4，同一车场的各入场通道依次导出。
4. 点击「开始导出」，在「任务进度」查看处理进度和日志。结束后，从结果区或「历史记录」打开时长汇总台账、通道汇总或输出目录。

### 台账要求

台账可以有多张工作表，其中须恰有一张可见工作表在前 100 行内的同一行包含 `地块名称` 和 `月总停车时长（小时）` 两个表头。地块名称使用文字，每个地块一行，名称须唯一。合计和说明行可保留。示例中的地块请替换为账号有权访问的项目。

### 平台查询和时长口径

- 查找路径为「项目管理 → 项目/编码 → 车场 → 记录查询 → 车辆进出记录」，导出文件从「报表汇总 → 报表导出下载」取得。账号登录和数据查询均使用[利民停车管理平台](https://s.qcyuns.com/)。
- 程序按地块名称匹配账号可见项目，结合名称规范化、后缀、关键词和既有别名匹配。匹配方式、搜索词、项目编码及待核对原因见台账副本的「车场查找与导出」。
- 「出入状态」留空，逐个查询可选入场通道。平台查询为零的通道会记入核对结果。下载报表会核对车场、入场通道、日期和记录条数。日期按入场记录的入场时间、出场记录的出场时间核验。
- 月总时长取通过核验报表中可解析的出场停车时长，按分钟累加后换算成小时，显示两位小数。入场记录和缺少有效时长的出场记录计入报表行数，时长合计仅包含有效的出场时长。
- 地块的通道报表均通过核验或查询为零后，才写入时长。有待核对的地块及已有公式的时长单元格保留原值。同订单号记录的拟扣减结果列为复核建议，台账填写值沿用报表口径。

## 输出文件与续跑

默认输出目录为 EXE 所在目录，可在界面中修改。每次新建导出按统计日期建子目录，例如 `2026-10-20至2026-11-20`。同一日期范围再次新建时使用 `_02` 等编号。源台账保留在原位置。

| 文件或目录 | 用途 |
| --- | --- |
| `原始报表/` | 平台下载的各入场通道 Excel 文件 |
| `车场与入场通道导出汇总.xlsx` | 车场及通道核对结果、通过核验的记录 |
| `<源台账名>_时长汇总.xlsx` | 更新后的台账副本，附「车场查找与导出」和「最终汇总」工作表 |
| `入场通道导出进度.json`、`任务结果.json` | 导出进度、任务结果和续跑记录 |
| `请求统计.json` | 记录所选并行数、实际参与线程、同时处理车场峰值、平台请求统计和总耗时，取得统计时生成 |

「最终汇总」包含关键词匹配数量、待核对地块、时长异常、重复订单核对以及检测到的原台账公式问题。台账副本在异常明细中只列需核对的行，完整的已核验进出记录在通道汇总文件中。

任务结束后会弹出结果。「已完成（有问题）」表示任务已结束，但有未匹配、未导出或未通过核验的项目等。可在「任务进度」或「历史记录」查看问题详情。如果记录提供「继续未完成」，应用会复用原任务目录和已完成的通道报表，已有汇总文件会保留，新文件会加 `_续跑` 等后缀。

更新客户端时，可以在关闭旧版后直接运行新版。历史记录和登录配置保存在当前 Windows 用户的 `%APPDATA%\ParkingReportWorkbench`。

## 从源码构建

准备 Windows x64、Python 3.13 和 Node.js 24（含 npm）。在 PowerShell 中进入仓库根目录，运行以下命令。

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
Set-Location desktop
npm ci
.\build.ps1
```

如果使用的 Python 3.13 已在 `PATH` 中，可用 `python -m venv .venv` 创建虚拟环境。

产物位于 `desktop/dist/ANPING.exe`。联网构建会下载 npm 依赖、Electron 和匹配 Patchright 版本的 Chromium，Python 构建依赖由 [`requirements-build.txt`](requirements-build.txt) 固定。分步构建和开发启动见[桌面客户端构建说明](desktop/README.md)。

下载的便携包可用 PowerShell 核对 SHA-256，并与对应 Release 页中的值比较。

```powershell
Get-FileHash -LiteralPath .\ANPING.exe -Algorithm SHA256
```
